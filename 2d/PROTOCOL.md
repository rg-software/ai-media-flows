# 2D experiment protocol

How we run 2D experiments so results are reproducible, comparable, and legible. This is the operational counterpart to `EXPERIMENTS-2D.md` (the log) and `ROADMAP-2D.md` (the plan).

## 1. Canonical example assets

We do **not** use ad-hoc/placeholder inputs. E1 generates a fixed, reusable asset set that the rest of the ladder consumes (E2 control, E3 cutout, E5 pixelate, E6 sprite, E7 tileable, E10 composition).

**Status: a production set, not a frozen baseline** (decided 2026-09-25). The assets are examples of the workflows and proofs of achievement, so they track current output and are regenerated as flows improve - what each asset *is* stays reproducible because `gen_assets.py` (prompts + seeds) is the source of truth, so the script is the stable artefact rather than the image. Consequence: when a flow is upgraded, re-generating the affected asset is correct, and an experiment that compared against the older render should say which it used. If a specific comparison ever needs a fixed historical render, freeze that one asset under a versioned id instead of freezing the set.

Generated by `scripts/gen_assets.py` — **the script is the source of truth** for prompts/seeds. Promote accepted results into ComfyUI `input/2d/` under the stable `id` filename so downstream workflows can reference them by name.

**Face-ID rule:** anything that embeds a face (InstantID, IPAdapter-FaceID, PuLID) needs the face to be **≥ ~112 px** in the reference. A 1024² full-body gives only ~60 px, so use a dedicated large-face portrait (`portrait_heroine`) as the identity source. `char_knight` is **unusable** for these tools — it is helmeted.

**Pixel art rule:** those models emit a *blocky canvas*; downscale **nearest** by the model's grid factor (16 for 16x@256², 8 for 24x-64x@512² and 128x@1024²) — never rely on the detector's auto-detection, and never feed it an already-downscaled image. See E5c/E5f.

Current canonical set is the **E1d** generation (RealVisXL_V5.0_fp16). If the base assets are ever regenerated, the derivatives above must be re-derived too (see E3b/E4b/E7c in `EXPERIMENTS-2D.md`).

## 2. Run protocol

- **One knob at a time.** When tuning, vary a single parameter and hold everything else fixed (notably the seed) — otherwise the cause of a change is unidentifiable.
- **Record every run** in `2d/EXPERIMENTS-2D.md`: model, prompt, negative, seed, size, steps, cfg, sampler/scheduler, workflow file, and output path. Verdict `PASS`/`MEH`/`BLOCKED` **with the why**.
- **Sweeps** produce a *labeled contact sheet* (all variants side by side, param in the label) rather than scattered runs — comparison requires simultaneity.
- **Prefer scripted runs** (`scripts/`) over GUI clicks: reproducible, diffable, replayable.

## 3. Evaluation

Visual judgement is ground truth; use numbers as a cheap cross-check, not a replacement.

- **Visual**: labeled grid per sweep. Reviewed by the user (aesthetic call) and by the agent (failure detection, recommendation).
- **Structure adherence** (ControlNet): canny the output, compare against the driving edge map (IoU / mean Chamfer distance).
- **Prompt adherence**: CLIP image↔text similarity using the checkpoint's own CLIP.
- Reject on: ignored control, washed-out/over-baked output, prompt collapse, visible artifacts.

## 4. Promotion and naming

- Raw outputs → ComfyUI `output/2D/<E#>/<id>_00001_.png` (transient, gitignored).
- Accepted assets → ComfyUI `input/2d/<id>.png` (stable names for downstream workflows).
- **Canonical concept art is versioned in the repo** at `assets/2d/<id>.png` (same `<id>` as above). This is the durable copy — the ComfyUI `input/` copy can be re-derived from it.
- Pipeline workflows → `2d/workflows/`; scaffolding → `2d/workflows/scratch/`.
- Experiment **evidence** (comparison sheets, contact sheets) → `2d/evidence/E<n>-<slug>.png` (tracked).
- Never commit model weights (`.gitignore` blocks `*.safetensors`, `*.ckpt`, etc.).

## 5. Reproduce from scratch

```bash
# on the ComfyUI box, in the repo clone
git pull
python scripts/gen_assets.py --token "$(head -1 ~/Projects-Git/ComfyUI/login/PASSWORD)"

# publish ComfyUI input/2d/ -> repo assets/2d/ (verifies md5; see script header)
scripts/publish_assets.sh
git add assets/2d && git commit -m "assets: <what>" && git push
```

**Always publish through the script.** Promotion is a separate step from generation, and skipping it leaves *stale* assets in the repo while the ComfyUI copy looks right — that is exactly what happened in E1d (repo `char_knight` stayed the old two-view E1b image). The script verifies hashes so this cannot pass silently.
