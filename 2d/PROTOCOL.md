# 2D experiment protocol

How we run 2D experiments so results are reproducible, comparable, and legible.
This is the operational counterpart to `EXPERIMENTS-2D.md` (the log) and `ROADMAP-2D.md` (the plan).

## 1. Canonical example assets

We do **not** use ad-hoc/placeholder inputs. E1 generates a fixed, reusable asset set that the
rest of the ladder consumes (E2 control, E3 cutout, E5 pixelate, E6 sprite, E7 tileable, E10 composition).

Generated by `scripts/gen_assets.py` — **the script is the source of truth** for prompts/seeds.
Promote accepted results into ComfyUI `input/2d/` under the stable `id` filename so downstream
workflows can reference them by name.

| id | purpose | feeds | prompt (abridged) | seed | size |
|---|---|---|---|---|---|
| `char_knight` | full-body character | E3 cutout, E6 sprite, consistency | heroic knight, ornate plate armor, standing, plain background | 1101 | 1024² |
| `prop_chest` | single prop | E3 cutout, 3D cross-check | fantasy treasure chest, 3/4 view, plain background | 1102 | 1024² |
| `env_cottage` | environment/building | E2 control, E10 composition | medieval cottage exterior, stone, thatch, warm windows | 1103 | 1024² |
| `bg_forest` | background plate | E9 outpaint, E10 composition | misty pine forest, layered depth, no characters | 1104 | 1024² |
| `tex_stone` | material/texture | E7 tileable, 3D texturing | seamless stone wall, flat, even lighting | 1105 | 1024² |

Conventions: plain/neutral background for cutout assets; no text/watermarks; SDXL native 1024²
(wide formats and outpaint are E9's job, not E1's).

Derived assets (produced by later stages, also versioned under `assets/2d/`):

| id | produced by | note |
|---|---|---|
| `prop_chest_cutout` | E3 `workflows/remove-bg.json` | RGBA cutout of `prop_chest` (BiRefNet) |

## 2. Run protocol

- **One knob at a time.** When tuning, vary a single parameter and hold everything else fixed
  (notably the seed) — otherwise the cause of a change is unidentifiable.
- **Record every run** in `2d/EXPERIMENTS-2D.md`: model, prompt, negative, seed, size, steps, cfg,
  sampler/scheduler, workflow file, and output path. Verdict `PASS`/`MEH`/`BLOCKED` **with the why**.
- **Sweeps** produce a *labeled contact sheet* (all variants side by side, param in the label)
  rather than scattered runs — comparison requires simultaneity.
- **Prefer scripted runs** (`scripts/`) over GUI clicks: reproducible, diffable, replayable.

## 3. Evaluation

Visual judgement is ground truth; use numbers as a cheap cross-check, not a replacement.

- **Visual**: labeled grid per sweep. Reviewed by the user (aesthetic call) and by the agent
  (failure detection, recommendation).
- **Structure adherence** (ControlNet): canny the output, compare against the driving edge map
  (IoU / mean Chamfer distance).
- **Prompt adherence**: CLIP image↔text similarity using the checkpoint's own CLIP.
- Reject on: ignored control, washed-out/over-baked output, prompt collapse, visible artifacts.

## 4. Promotion and naming

- Raw outputs → ComfyUI `output/2D/<E#>/<id>_00001_.png` (transient, gitignored).
- Accepted assets → ComfyUI `input/2d/<id>.png` (stable names for downstream workflows).
- **Canonical concept art is versioned in the repo** at `assets/2d/<id>.png` (same `<id>` as above).
  This is the durable copy — the ComfyUI `input/` copy can be re-derived from it.
- Pipeline workflows → `2d/workflows/`; scaffolding → `2d/workflows/scratch/`.
- Never commit model weights (`.gitignore` blocks `*.safetensors`, `*.ckpt`, etc.).

## 5. Reproduce from scratch

```bash
# on the ComfyUI box, in the repo clone
git pull
python scripts/gen_assets.py --token "$(head -1 ~/Projects-Git/ComfyUI/login/PASSWORD)"

# publish the accepted set to the versioned repo copy
mkdir -p assets/2d
for id in char_knight prop_chest env_cottage bg_forest tex_stone; do
  cp -f ~/Projects-Git/ComfyUI/input/2d/$id.png assets/2d/$id.png
done
git add assets/2d && git commit -m "assets: 2d E1b concept art set" && git push
```
