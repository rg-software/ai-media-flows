So it does help - more than expected, and for a specific reason worth knowing: repeating each pose gives the temporal smoother more consistent samples to average against, so an isolated pop is more easily absorbed. **But duplication cannot repair a wrong pose** - the largest flip survived almost intact (162 deg) and now simply lasts twice as long. | E2  | 2026-09-27 | the flow ignored both of its inputs | video reference (whole flow) | `pink_hair_mech_arms_ref.png` + `street_dance_drive.mp4` (the upstream example pair)        | diagnosis of E1's output, then the fix; A/B by swapping the reference image and the driving clip                                                                                          | `output/animation/wan_animate_motion_0006-0010_.mp4`; sheets `output/animation/ref_vs_output.png`, `output/animation/fixed_ref_check.png`, `output/animation/official_model_check.png` | **PASS** (two independent bugs, both found and fixed) | E1 called the result 'identity-preserved' - it was not. The output was a **cartoon girl in an orange dress** from a **photoreal** pink-haired reference, and the reference was never actually compared: the frames were only checked against each other. The measurement that exposed it is the useful part: **swapping the reference changed the output by exactly 0.00**, which cannot happen if the image is being used. TWO bugs stacked. **(1) Wiring.** `WanAnimate2ToVideo` does its work by RETURNING modified conditioning - the VAE-encoded reference as `concat_latent_image` + a `concat_mask` (the actual identity mechanism), `clip_vision_output`, and the pose branch's `pose_video_latent`, `clip_vision_output_pose`, `cross_attn_pose`. The flat rebuild fed `SamplerCustom.positive/negative` the raw `CLIPTextEncode` outputs instead, leaving that node's own conditioning outputs with **links=[]** - so every one of those values was dropped and the sampler ran plain text-to-video. CONDITIONING -> CONDITIONING type-checks perfectly, so every gate passed and the graph ran to completion. **(2) The model.** Even with the wiring fixed, swapping the *driving clip* still changed nothing (0.00), while the reference now worked - a clean split, because the reference path is generic Wan I2V and the pose branch exists only in the animate2 class. Wan-Animate-2's identity lives in the file's **metadata**: `__metadata__ = {"config": {"transformer": {"model_type": "animate2"}}}`, which ComfyUI's detector lets override its key heuristic - and a **GGUF carries no such config**, so the identical weights (shapes verified equal to the official model) loaded as `i2v` and the log said `Requested to load WAN21`. Fixed by loading the official `wan_animate_2_int8_convrot.safetensors`, after which the log says `WAN_Animate2`. **Result:** the same reference character now animates, and the driving clip genuinely determines the motion (dance clip -> lunges and turns, water-glass clip -> clasped hands); temporal variance went 0.93 -> 50.4 and the drive-swap delta 0.00 -> 49.6. **Lesson, and the reason this is written down:** a quantiser is not a transparent size reduction when the model's identity is metadata. Also: 'it runs' is not 'it works' - the tell was two dead output links and one log line. |
